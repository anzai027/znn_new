# 第一个根本问题：平滑以后，精确跟踪移动解在结构上就做不到了

我们的原模型 \(p=1\) 是

\[
\dot g
=
-\gamma\frac{s}{\|s\|},
\qquad
s=J^T\xi.
\]

这个式子在

\[
s=0
\]

处不连续。

理论上，它可以按照 nonsmooth / sliding-mode 的方式理解：即使到达误差面，也可能存在一个“等效速度”，继续跟着移动的 \(g^*(t)\) 走。

但你们为了让 MATLAB 能算，把它改成：

\[
\boxed{
\dot g
=
-\gamma
\frac{s}{\sqrt{\|s\|^2+\varepsilon^2}}
}
\tag{1}
\]

这个改动看起来很小，但性质变了。

因为当

\[
\xi=0
\]

时：

\[
s=J^T\xi=0.
\]

那么平滑模型一定给出：

\[
\boxed{\dot g=0}.
\]

可是 TVQP 的理论解是：

\[
g^*=g^*(t),
\]

一般有：

\[
\boxed{\dot g^*(t)\neq0}.
\]

于是会发生什么？

假设这一瞬间你完美追上了：

\[
g=g^*(t).
\]

模型说：

\[
\dot g=0,
\]

但是目标继续运动：

\[
\dot g^*\neq0.
\]

所以马上就会再次产生误差。

也就是说：

\[
\boxed{
\text{平滑的纯反馈 GNN 必然是“目标跑开以后才追”，存在 tracking lag。}
}
\]

这正好解释你图里看到的情况：

状态轨迹看起来跟得挺好，但是

\[
\|\xi\|
\]

会周期性冒出明显的峰值。

所以这个现象不是偶然。

# 第二个问题更严重：\(J^T\xi\) 把 Jacobian 的病态程度“平方”了

这可能是当前第一版模型最值得改的地方。

我们使用：

\[
s=J^T\xi.
\]

假设已经比较接近理论解：

\[
e=g-g^*.
\]

局部可以近似：

\[
\xi\approx Je.
\]

那么：

\[
s
=
J^T\xi
\approx
J^TJe.
\]

也就是说，真正控制误差的是：

\[
\boxed{J^TJ}.
\]

如果 \(J\) 的最小奇异值是

\[
\sigma_{\min}(J)=m,
\]

那么：

\[
J^TJ
\]

的最小特征值是：

\[
\boxed{m^2}.
\]

所以条件数实际上被平方了。

你们的数据非常明显地暴露了这个问题。

在 \(\varepsilon=0.01\) 的 Example 2 里，我从保存的数据看到：

\[
\sigma_{\min}(J)
\]

最低大约只有

\[
\boxed{0.0028}.
\]

而且在一个非常典型的时刻：

\[
t=6.31\text{ s},
\]

你们的数据是：

\[
\|\xi\|\approx0.168,
\]

已经是挺大的残差了，但是：

\[
\boxed{\|J^T\xi\|\approx0.00230}.
\]

也就是说：

> KKT/PFB 明明还错得不少，但是经过 \(J^T\) 一乘以后，GNN 觉得“梯度已经非常小”。

这就是非常典型的 ill-conditioning。

而我们的平滑公式偏偏又根据

\[
\|J^T\xi\|
\]

决定速度。

此时实际速度只有：

\[
100
\frac{0.00230}
{\sqrt{0.00230^2+0.01^2}}
\approx
\boxed{22.4}.
\]

本来 \(\gamma=100\)，理论最大速度是 100。

结果由于：

\[
J^T\xi
\]

太小，

系统只用了大约 22 的速度。

所以这里出现了一个非常糟糕的组合：

\[
\boxed{
\text{残差还很大}
\quad+\quad
J\text{ 条件不好}
\quad\Rightarrow\quad
J^T\xi\text{ 很小}
}
\]

然后：

\[
\boxed{
\text{平滑函数认为应该减速}
}
\]

恰恰在最需要追的时候慢下来了。

# 第三个问题：\(\varepsilon\) 存在明显的“精度—数值稳定性矛盾”

这个实验已经几乎把规律画出来了。

平滑模型：

\[
\dot g
=
-\gamma
\frac{s}{\sqrt{\|s\|^2+\varepsilon^2}}.
\]

当：

\[
\|s\|\ll\varepsilon
\]

的时候，

\[
\sqrt{\|s\|^2+\varepsilon^2}
\approx\varepsilon,
\]

所以：

\[
\boxed{
\dot g
\approx
-\frac{\gamma}{\varepsilon}s.
}
\]

这实际上变成了一个高增益线性梯度系统。

所以：

\[
\varepsilon\downarrow
\]

会让：

\[
\frac{\gamma}{\varepsilon}\uparrow.
\]

例如：

\[
\gamma=100.
\]

当：

\[
\varepsilon=10^{-2},
\]

局部增益是：

\[
10^4.
\]

当：

\[
\varepsilon=10^{-3},
\]

就变成：

\[
10^5.
\]

当：

\[
\varepsilon=10^{-4},
\]

就是：

\[
10^6.
\]

所以结果自然变成：

\[
\boxed{
\varepsilon\text{ 小}
\Rightarrow
\text{误差小，但 ODE 极度 stiff}
}
\]

而：

\[
\boxed{
\varepsilon\text{ 大}
\Rightarrow
\text{好算，但是 tracking lag 大}
}
\]

你们实验正好验证了这个规律。

因此我不建议继续把主要精力花在“找一个神奇的 \(\varepsilon\)”上。

因为这个 trade-off 是公式本身带来的。

# 第四个问题：\(\gamma=100\) 对整个 \(g\) 而言甚至不够快

这个发现很重要。

你们现在的状态不是只有：

\[
x,
\]

而是：

\[
g=
[x;\mu_1;\mu_2].
\]

对于原始 \(p=1\) 模型：

\[
\|\dot g\|=\gamma=100.
\]

所以整个七维状态的最大运动速度就是：

\[
100.
\]

我用你保存的 Example 2 理论参考解 \(g^*(t)\) 做了数值差分。

得到：

\[
\boxed{
\max_t\|\dot g^*(t)\|
\approx141.1.
}
\]

但：

\[
\gamma=100.
\]

也就是说，在某些时刻：

\[
\boxed{
\text{即使方向完全正确，GNN 也跑不过理论解。}
}
\]

这是一个非常直接的物理限制。

更有意思的是，单独看：

\[
x^*(t)
\]

它的最大速度只有大约：

\[
\boxed{21.5}.
\]

真正突然跑得特别快的是：

\[
\mu_1,\mu_2
\]

这些乘子。

尤其是在 active constraint 切换附近。

例如大约：

\[
t=9.74\text{ s}
\]

时，理论完整状态速度：

\[
\|\dot g^*\|\approx141.
\]

主要就是乘子的变化造成的。

所以现在这个：

\[
\boxed{\text{把 }x,\mu_1,\mu_2\text{ 全部放在一个范数里统一归一化}}
\]

其实也有问题。

因为 primal 和 dual 的运动尺度完全不一样。

# 第五个问题：不平滑版的“爆炸结果”不能直接说明理论模型发散

这个也必须分清。

原来不平滑的 \(p=1\) 模型理论上满足：

\[
\|\dot g\|=\gamma
\]

只要没有噪声就是：

\[
100.
\]

所以任意时间：

\[
\|g(t)-g(0)\|\le100t
\]

应该成立。

但是你们保存的原公式实验中，`motion.m` 已经检查出来：

无噪声和 cosine 那些“成功跑完”的 GNN 轨迹**明显违反了这个速度上限**。

例如原无噪声结果 `motion=0`，速度上限检查有巨大的 excess。

所以那些 RMSE 几百、几万甚至几十万的结果：

\[
\boxed{\text{主要是 ode15s 对不连续向量场的数值失真}}
\]

不能简单解释成：

> 数学上的原始 GNN 本身一定发散。

这反而说明：

\[
\boxed{
\text{普通 MATLAB ODE solver 不适合直接积分 }s/\|s\|
}
\]

因为它不是一个普通光滑 ODE。

所以你们平滑这个实验是有意义的：它排除了大量假的数值跳变，然后暴露出了**真正的模型 tracking 问题**。

# 所以我认为第二版最应该改的，不是 Fixed-Time，而是“梯度方向”

目前：

\[
\boxed{s=J^T\xi}
\]

是普通 steepest gradient。

我现在最推荐你们下一步尝试的是：

\[
\boxed{\text{Preconditioned / Gauss–Newton GNN}}
\]

定义：

\[
\boxed{
s=J^T\xi
}
\]

然后不要直接使用 \(s\)，而是求：

\[
\boxed{
d=
(J^TJ+\lambda I)^{-1}J^T\xi.
}
\tag{2}
\]

其中：

\[
\lambda>0
\]

是一个小的阻尼项。

然后动力学改为：

\[
\boxed{
\dot g
=
-\gamma
\frac{d}
{\sqrt{\|d\|^2+\varepsilon^2}}.
}
\tag{3}
\]

我觉得这个模型现在比原第一版值得实验得多。

---

## 为什么这个改动可能正好解决你们的数据问题？

还看局部误差：

\[
\xi\approx Je.
\]

原模型：

\[
J^T\xi
\approx
J^TJe.
\]

所以：

\[
\boxed{s\approx J^TJe}.
\]

而新的方向：

\[
d
=
(J^TJ+\lambda I)^{-1}J^T\xi.
\]

如果 \(\lambda\) 很小，而且 \(J\) 可逆，那么：

\[
d
\approx
(J^TJ)^{-1}J^TJe.
\]

于是：

\[
\boxed{d\approx e}.
\]

漂亮的地方就在这里。

原来：

\[
\boxed{J^TJ\text{ 把误差扭曲了}}
\]

现在：

\[
\boxed{(J^TJ)^{-1}\text{ 把这个扭曲基本补回来}}
\]

所以不再那么怕：

\[
\sigma_{\min}(J)
\]

很小。

---

而且我们可以更具体地解释为什么它能减少你现在的 tracking lag。

原平滑 GNN 在零点附近：

\[
\dot e
\approx
-\frac{\gamma}{\varepsilon}J^TJe
-\dot g^*.
\]

假设达到准稳态：

\[
\dot e\approx0.
\]

那么：

\[
e_{\rm ss}
\approx
-\frac{\varepsilon}{\gamma}
(J^TJ)^{-1}\dot g^*.
\]

因此：

\[
\boxed{
\|e_{\rm ss}\|
\lesssim
\frac{\varepsilon}
{\gamma\sigma_{\min}^2(J)}
\|\dot g^*\|.
}
\tag{4}
\]

看到最危险的东西了吗？

\[
\boxed{\frac1{\sigma_{\min}^2(J)}}.
\]

如果：

\[
\sigma_{\min}(J)=0.01,
\]

那么：

\[
\frac1{\sigma_{\min}^2}=10000.
\]

这完全能解释为什么看起来 \(\varepsilon\) 已经很小了，tracking error 仍然不小。

---

而用了预条件以后：

\[
d\approx e.
\]

零点附近变成：

\[
\dot e
\approx
-\frac{\gamma}{\varepsilon}e
-\dot g^*.
\]

于是：

\[
\boxed{
e_{\rm ss}
\approx
-\frac{\varepsilon}{\gamma}\dot g^*.
}
\tag{5}
\]

原来那个：

\[
\frac1{\sigma_{\min}^2(J)}
\]

消失了。

这个不是“随便改一个公式”。

它是直接针对你实验暴露出来的：

\[
\boxed{J\text{ 病态 }\rightarrow J^T\xi\text{ 太小}}
\]

这个问题设计的。

# 第二个我建议同时测试的改动：不要再给 \(x,\mu_1,\mu_2\) 共用一个速度预算

可以把：

\[
d=
\begin{bmatrix}
d_x\\
d_{\mu_1}\\
d_{\mu_2}
\end{bmatrix}
\]

分别更新：

\[
\boxed{
\dot x
=
-\gamma_x
\frac{d_x}
{\sqrt{\|d_x\|^2+\varepsilon_x^2}}
}
\]

\[
\boxed{
\dot\mu_1
=
-\gamma_{\mu_1}
\frac{d_{\mu_1}}
{\sqrt{\|d_{\mu_1}\|^2+\varepsilon_\mu^2}}
}
\]

\[
\boxed{
\dot\mu_2
=
-\gamma_{\mu_2}
\frac{d_{\mu_2}}
{\sqrt{\|d_{\mu_2}\|^2+\varepsilon_\mu^2}}.
}
\tag{6}
\]

原因就是我们刚才发现：

\[
\max\|\dot x^*\|\approx21.5
\]

但是：

\[
\max\|\dot g^*\|\approx141.
\]

主要是 dual variables 突然变化。

所以完全可以考虑：

\[
\gamma_x
\]

比较温和，而

\[
\gamma_\mu
\]

允许更大。

这样不会因为 multiplier 突然变化，把整个七维向量的统一速度预算吃完。

# 第三个改动：\(\gamma\) 不能一直固定为 100

至少作为诊断实验，你们下一轮应该先试：

\[
\boxed{
\gamma=100,\;150,\;200,\;300
}
\]

尤其我会优先看：

\[
\boxed{\gamma=200}.
\]

不是因为 200 一定最好，而是你这个 Example 2 保存的参考解已经告诉我们：

\[
\max\|\dot g^*\|\approx141.
\]

所以：

\[
\gamma=100
\]

本身就存在明显速度不足。

如果：

\[
\gamma=200
\]

以后误差峰值明显降低，就证明“moving-root speed limit”确实是原因之一。

但这还只是诊断。

最终最好不要简单说：

> 把 \(\gamma\) 调大就行。

因为这会增加 stiffness 和噪声敏感性。

后面可以设计真正的 variable gain。

而且我反而建议**不要直接照抄 VFCR 那种只随时间下降的 gain**。

更适合你们的是 error-dependent gain，例如：

\[
\boxed{
\gamma(\xi)
=
\gamma_{\min}
+
(\gamma_{\max}-\gamma_{\min})
\frac{\|\xi\|^q}
{\|\xi\|^q+c^q}
}
\tag{7}
\]

误差大：

\[
\gamma\rightarrow\gamma_{\max}
\]

误差小：

\[
\gamma\rightarrow\gamma_{\min}.
\]

如果后面突然发生 active-set switch、残差重新增大，gain 又会自己升起来。

这比“时间越晚 gain 永远越小”更适合这种 TVQP。

# 但是还有一个更深的问题：如果坚持 smooth + exact tracking，就必须有预测项

这一点很关键。

只要我们的模型是：

\[
\dot g=F(\xi)
\]

而且平滑以后：

\[
F(0)=0,
\]

那么移动解处：

\[
\xi=0
\]

就一定得到：

\[
\dot g=0.
\]

所以：

\[
\boxed{
\text{纯平滑误差反馈无法对移动根做到严格零误差持续跟踪。}
}
\]

要彻底解决，有两条路。

第一条是坚持 FTCGNN 原来的 nonsmooth 思路：

\[
\operatorname{Sgn}(s)
\]

按照微分包含 / sliding-mode 理论处理，并且不用普通 `ode15s`，而是使用适合 nonsmooth dynamics 的 implicit/discrete solver。

这条路理论上更“纯 GNN”，也能保留 exact finite-time 的味道，但实现和证明会难不少。

另一条路是允许一个 predictor/feedforward：

\[
\boxed{
\dot g
=
\hat v(t)
-
\gamma
\frac{d}{\sqrt{\|d\|^2+\varepsilon^2}}
}
\tag{8}
\]

其中：

\[
\hat v(t)
\]

估计最优解本身的运动速度。

比如不直接使用

\[
\dot G,\dot P,\cdots
\]

而利用相邻时刻的数据做预测。

这样即使：

\[
\xi=0,
\]

仍然有：

\[
\dot g=\hat v\neq0,
\]

就可以跟着最优解走。

不过这条路就需要重新讨论：

> 我们还能不能把它称为“完全 derivative-free”？

所以这是后面更深入的一条路线，不建议现在马上加入。

所以如果让我现在给这次实验下一个简短结论，我会写：

> **第一版 \(J^T\xi\)-GNN 证明了 GNN 化 TVQP 是可运行的，但普通梯度结构对 KKT/PFB Jacobian 的病态性高度敏感；平滑虽然解决了不连续模型的数值失真，却引入了不可避免的时变跟踪滞后，并形成精度与 stiffness 的权衡。因此下一版不应继续单纯调整平滑参数，而应优先研究 Jacobian 预条件/Gauss–Newton 梯度、primal-dual 分块增益以及自适应增益。**

还有一点其实挺值得高兴：你们的模型并不是“完全没效果”。在 \(\varepsilon=10^{-3}\) 的五组 Gaussian 噪声实验里，GNN 全部跑完，delta-RMSE 中位数约

\[
0.00773,
\]

而 VFCR-ZNN 是约

\[
0.01975.
\]

这不能据此说 GNN 已经比 VFCR 强，因为实验目的、平滑方式和计算代价都不同；但它至少说明：

\[
\boxed{\text{这个方向还有值得继续改的信号，而不是应该直接放弃。}}
\]

我目前会把 **“damped Gauss–Newton / preconditioned GNN”** 作为下一版第一优先级，因为它是这次实验数据直接推出来的改进，而不是凭感觉往模型里继续堆模块。
