## 一、我认为报告最重要的四个结论

第一，**公式实现基本没错。**

报告检查了 360 个 GNN 公式测点，Jacobian 最大相对差分误差约

\[
4.09\times10^{-10}.
\]

所以现在不应该继续主要怀疑“是不是 \(J\) 推错了”“是不是符号错了”。:chatgpt-content-reference{index="1"}

第二，**M3 的 Gauss–Newton / 预条件方向是有效的。**

同样 \(\gamma=200\) 时：

\[
\text{M2 的 }x\text{ RMSE}\approx1.997\times10^{-2},
\]

而：

\[
\text{M3}\approx3.965\times10^{-4}.
\]

提升大约：

\[
\boxed{50.4\text{ 倍}}
\]

而函数调用次数还从约 20971 降到 4941。:chatgpt-content-reference{index="2"}

所以：

\[
\boxed{
d=(J^TJ+\lambda I)^{-1}J^T\xi
}
\]

这条路我建议**继续保留作为下一版的核心方向**。

第三，**M4 的分块归一化不值得作为主线继续。**

报告已经给出了严格凸反例：M3 下

\[
\dot V<0,
\]

而 M4 可以出现

\[
\dot V>0,
\]

甚至最初一段 \(V\) 上升到初值的约 2.9 倍。:chatgpt-content-reference{index="3"}

所以之前“给 \(x,\mu_1,\mu_2\) 分别归一化”这个想法要收回来。

问题不是“分块思想完全不能研究”，而是：

\[
\boxed{\text{不能破坏原来联合下降方向。}}
\]

第四，也是最关键的：

\[
\boxed{\text{平滑纯反馈结构天然存在时变 tracking lag。}}
\]

现在平滑模型本质上都是：

\[
\dot g=F(\xi),
\qquad F(0)=0.
\]

但理论最优根 \(g^*(t)\) 自己在运动。

当你终于做到：

\[
\xi=0
\]

的时候，模型给出：

\[
\dot g=0,
\]

可是：

\[
\dot g^*(t)\neq0.
\]

所以目标马上又跑开。

报告通过冻结实验、高增益实验、题目速度实验都支持了这个判断。:chatgpt-content-reference{index="4"}

因此：

\[
\boxed{\text{这不是继续把 }\varepsilon\text{ 调小就能根治的问题。}}
\]

# 二、所以我现在最推荐的第二代模型：Predictor + Preconditioned GNN

这是我觉得报告给出的最自然下一步。

我们仍然保留：

\[
\xi(g,t)
\]

以及：

\[
J=\frac{\partial\xi}{\partial g}.
\]

纠错方向继续使用已经被实验验证有效的 M3：

\[
\boxed{
d_c
=
(J^TJ+\lambda I)^{-1}J^T\xi.
}
\tag{1}
\]

这里 \(c\) 表示 correction。

然后我们增加一个**预测项 predictor**。

为什么？

因为理论根满足：

\[
\xi(g^*(t),t)=0.
\]

对时间求导：

\[
J(g^*,t)\dot g^*
+
\xi_t(g^*,t)
=
0.
\]

所以理想的根运动速度满足：

\[
\boxed{
J\dot g^*
=
-\xi_t.
}
\]

如果我们知道 \(\xi_t\)，就可以预测目标接下来往哪里跑。

但我们的研究又不希望重新显式计算：

\[
\dot G,\dot P,\dot Q,\dot h,\dot u,\dot v.
\]

怎么办？

可以**不用解析导数，而用相邻时刻的数据估计**。

例如：

\[
\boxed{
\widehat{\xi_t}
=
\frac{
\xi(g_k,t_k)-\xi(g_k,t_k-\Delta t)
}{
\Delta t
}.
}
\tag{2}
\]

这里特别注意：

两项使用的是**同一个 \(g_k\)**。

这样差出来的主要就是：

> “题目本身随时间怎么变化”

而不是把 \(g\) 自己运动的影响混进去。

---

然后定义预测速度：

\[
\boxed{
d_p
=
-(J^TJ+\lambda I)^{-1}
J^T\widehat{\xi_t}.
}
\tag{3}
\]

于是我们的第二代候选模型可以写成：

\[
\boxed{
\dot g
=
d_p
-
\gamma
\frac{d_c}
{\sqrt{\|d_c\|^2+\varepsilon^2}}.
}
\tag{4}
\]

这一个式子我觉得非常值得做下一轮实验。

---

## 三、为什么这个模型正好解决报告暴露的问题？

原来的 M3 只有：

\[
-\gamma
\frac{d_c}{\sqrt{\|d_c\|^2+\varepsilon^2}}.
\]

它的逻辑是：

> 有误差 → 追；
>
> 没误差 → 停。

所以永远慢目标一步。

而新模型变成：

\[
\boxed{\text{预测目标移动}}
+
\boxed{\text{纠正剩余误差}}.
\]

即：

\[
\underbrace{d_p}_{\text{目标往哪跑}}
-
\underbrace{\gamma
\frac{d_c}{\sqrt{\|d_c\|^2+\varepsilon^2}}}_{\text{我和目标还差多少}}.
\]

当：

\[
\xi=0
\]

时：

\[
d_c=0,
\]

但：

\[
d_p
\]

通常不为零。

所以：

\[
\boxed{
\xi=0
\not\Rightarrow
\dot g=0.
}
\]

这正是原平滑模型最缺的能力。

# 四、这还能保留你们原来的卖点吗？

基本可以，但表述要稍微变化。

不能再说：

\[
\boxed{\text{完全不使用任何导数信息}}
\]

因为我们在用时间差分估计。

但是仍然可以比较准确地说：

\[
\boxed{
\text{不需要显式提供或解析计算 }
\dot G,\dot P,\dot Q,\dot h,\dot u,\dot v.
}
\]

也就是说，我们需要的只是连续两个时间点的：

\[
G(t),P(t),Q(t),h(t),u(t),v(t)
\]

或者直接重新计算：

\[
\xi(g,t).
\]

这个定位其实依然很有价值。

# 五、\(\lambda\) 也需要改，不能一直固定

报告发现尖峰处：

\[
\sigma_{\min}(J)\approx0.001072.
\]

而：

\[
\lambda=10^{-6}
\]

已经和：

\[
\sigma_{\min}^2(J)
\]

是同一个量级。

所以最弱方向经过 M3 后只保留约：

\[
0.535.
\]

:chatgpt-content-reference{index="5"}

这说明：

\[
\boxed{\lambda\text{ 太大，会重新把困难方向压掉；}}
\]

但是：

\[
\boxed{\lambda\text{ 太小，又会让求解病态。}}
\]

所以我不建议下一轮继续只用固定：

\[
10^{-6}.
\]

可以先做一个简单的 condition-aware damping。

比如：

\[
\boxed{
\lambda(t)
=
\max
\left(
\lambda_{\min},
\kappa\sigma_{\min}^2(J)
\right).
}
\tag{5}
\]

例如先试：

\[
\kappa=0.05,\quad0.1.
\]

如果：

\[
\lambda=0.1\sigma_{\min}^2,
\]

那么最弱方向保留比例：

\[
\frac{\sigma_{\min}^2}
{\sigma_{\min}^2+\lambda}
=
\frac1{1.1}
\approx0.91.
\]

比现在的 0.535 好得多。

当然这只是候选设计，实验后再判断。

# 六、不要再做 M4 那种“各块各走各的”，改成共同缩放

报告已经证明 M4 可能破坏下降方向，所以如果我们仍然担心：

\[
x,\mu_1,\mu_2
\]

的尺度和速度不一样，可以换一种方式。

先求统一方向：

\[
d=
\begin{bmatrix}
d_x\\
d_{\mu_1}\\
d_{\mu_2}
\end{bmatrix}.
\]

然后不改变方向，只乘一个共同正数：

\[
\boxed{
\dot g=-\alpha d.
}
\]

如果需要限制各部分速度，可以选：

\[
\boxed{
\alpha
=
\min
\left\{
\alpha_0,\,
\frac{v_x}{\|d_x\|},\,
\frac{v_{\mu_1}}{\|d_{\mu_1}\|},\,
\frac{v_{\mu_2}}{\|d_{\mu_2}\|}
\right\}.
}
\tag{6}
\]

这样三个块仍然按照原来的比例一起移动。

也就是：

\[
\boxed{\text{限速，但不改变方向。}}
\]

这比 M4 “每个块自己归一化”安全得多。

# 七、我觉得还应该增加“变量尺度归一化”

报告发现：

\[
\max\|\dot x^*\|
\]

其实并不特别大；

真正的尖峰来自：

\[
\mu_1,\mu_2.
\]

完整 \(g^*\) 的速度峰可以达到：

\[
\boxed{\approx4735.7}
\]

而乘子部分占了绝大部分。:chatgpt-content-reference{index="6"}

所以另外一个值得研究的方向不是简单让 \(\gamma\) 变成 5000，而是：

\[
\boxed{\text{先给 primal / dual 做尺度变换。}}
\]

例如：

\[
g=Dz
\]

其中：

\[
D=
\operatorname{diag}
(d_xI,d_{\mu_1}I,d_{\mu_2}I).
\]

然后在 \(z\) 空间求梯度。

对应 Jacobian：

\[
\widetilde J=JD.
\]

然后：

\[
\boxed{
d_z
=
(\widetilde J^T\widetilde J+\lambda I)^{-1}
\widetilde J^T\xi.
}
\]

最后：

\[
\dot g=D\dot z.
\]

这个和 M4 的区别非常重要：

M4 是：

> 求完一个正确联合方向以后，再把三个部分分别扭曲。

而变量 scaling 是：

> 从一开始就在一个重新定义的度量空间里求一个整体一致方向。

后者理论上更干净。

d_p,

这会比单纯暴力提高反馈增益漂亮很多。

# 九、Variable gain 应该怎么做，我现在也会改建议

之前我们考虑过直接搬 VFCR 那个随时间变化的：

\[
\rho(t).
\]

看完这个报告后，我觉得**不应该原样搬**。

因为你们的问题在 active-set 切换时会突然产生：

\[
\boxed{\text{速度尖峰}}.
\]

这可能发生在仿真的中后段。

如果 variable gain 只是：

> 随着时间越来越小

那恰好可能在最需要高增益的时候：

\[
\rho(t)
\]

已经降低了。

所以如果后面加 variable gain，我现在更推荐：

\[
\boxed{
\gamma(t)
=
\gamma_0
+
k_v\|d_p(t)\|
+
k_e\frac{\|\xi\|^q}{c^q+\|\xi\|^q}.
}
\tag{7}
\]

逻辑是：

目标运动快：

\[
\|d_p\|\uparrow
\Rightarrow
\gamma\uparrow.
\]

误差突然变大：

\[
\|\xi\|\uparrow
\Rightarrow
\gamma\uparrow.
\]

稳定以后：

\[
\gamma\downarrow.
\]

这比“单纯根据绝对时间降低增益”更适合你们这个 TVQP。

# 十、\(\delta\) 不能忽略，它已经成为最终误差的一部分

报告有一个特别重要的数字。

当：

\[
\gamma=5000
\]

以后，对**扰动 PFB 解**的 RMSE 已经：

\[
1.43\times10^{-5}.
\]

可是对原始真实最优解的 RMSE 仍然大约：

\[
4.925\times10^{-4}.
\]

:chatgpt-content-reference{index="9"}

这意味着：

> GNN 已经追得挺好了，但是它追的是 perturbed PFB root，而这个 root 本身和真正 QP 解有差异。

所以后面参数实验一定不能只扫：

\[
\gamma,\varepsilon,\lambda.
\]

还必须扫：

\[
\boxed{\delta}.
\]

但是：

\[
\delta\downarrow
\]

又会让 complementarity 更尖锐、Jacobian 更病态、active-set switch 更剧烈。

所以这里存在另一个 trade-off：

\[
\boxed{
\delta\text{ 大}
\Rightarrow
\text{好算，但有建模偏差}
}
\]

\[
\boxed{
\delta\text{ 小}
\Rightarrow
\text{解更准，但问题更尖锐}
}
\]

这可能以后也可以做成 continuation / adaptive PFB parameter。

# 十一、我建议接下来暂时不要碰 Fixed-Time

这个建议和我们几个月前不一样。

现在实验已经告诉我们：

**最基础的时变 tracking mechanism 还没彻底解决。**

这时候直接加：

\[
-E^\alpha-E^\beta
\]

去追 fixed-time，可能只是把一个“追不住移动根”的模型变成一个“更猛烈地追不住移动根”的模型。

所以我建议研究顺序改成：

1. **M3 保留，作为 baseline。**
2. **加入 predictor，验证 tracking lag 是否显著消失。**
3. **处理 \(\lambda\)、变量尺度和 active-set switch。**
4. **做完整噪声实验。**
5. 等这个版本真正稳定以后，再研究 Fixed-Time / variable gain。

这个顺序我现在认为比之前更稳。
